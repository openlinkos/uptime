# LinkOS Status

[uptime.linkos.org](https://uptime.linkos.org) 显示 [LinkOS](https://linkos.org) 各项服务的实时状态，每分钟从洛杉矶和中国大陆各检测一次。状态页不依赖 GitHub，在大陆也能正常打开。LinkOS 是 [OpenLinkOS](https://openlinkos.com) 运营的托管服务线。

LinkOS Status shows the live status of the LinkOS services, checked every minute from Los Angeles and from mainland China. Outages are reported as issues in this repository.

## 检测什么

| 分组 | 检测内容 |
| --- | --- |
| Overseas - Los Angeles | 五个镜像加速域名（缓存可用才算正常）、linkos.org、openlinkos.com；HTTPS 证书剩余不到 7 天也算异常 |
| Mainland China - Shanghai BGP | 从上海 BGP 线路检测五个镜像加速域名和 linkos.org。Reachability 表示这条线路能不能访问 LinkOS：全部检测都失败才算异常，耗时是各项的平均值 |
| Mainland China - Zhejiang Telecom | 从浙江电信线路检测，内容同上 |

怎么看结果：

- 海外和大陆都异常：服务本身出了问题。
- 只有大陆异常：大陆到服务的线路有问题，海外用户不受影响。
- 只有一个大陆检测点异常：多半只是那条线路的问题。
- 大陆检测失败后隔 5 秒重试，最多 3 次，3 次都失败才记为异常，所以偶发的跨境丢包、几秒钟的服务重启不会显示出来。鼠标停在红色的格子上，可以看到失败的原因。

## 故障通知

故障会在本仓库开 [issue](https://github.com/openlinkos/uptime/issues)：某项服务连续 3 次检测异常时，自动开一个标题以 `alert(gatus):` 开头的 issue，恢复后自动关闭。大陆检测点只在整条线路都不通时开 issue。

想收到通知，可以 Watch 本仓库，选 Custom → Issues。

## 仓库内容

- [`gatus/`](gatus)：状态页的检测项和告警规则（[Gatus](https://github.com/TwiN/gatus) 的配置）。这就是线上正在用的配置，合入后几分钟内生效。
- [`probe/`](probe)：大陆检测点运行的检测脚本。
- [`history/`](history)、[`api/`](api)、[`graphs/`](graphs)：2023-12 到 2026-10 使用 [Upptime](https://upptime.js.org) 时的数据，原样保留；那段时间的 issue 也保留着。Upptime 靠 GitHub Actions 定时检测，实际间隔常常长达几个小时，只能从海外检测，状态页在大陆也打不开，所以换成了现在的方式。
